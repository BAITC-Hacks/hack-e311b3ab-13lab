# Ручная сверка источников

Обновление: слой сверки объединён с доступными локальными улучшениями анализа. Актуальные результаты, ограничения и статус приёмки — в `INTEGRATION_VALIDATION.md`; исторические цифры проверки ниже относятся к предыдущему этапу.

Локальная доработка актуального GitHub main `ff7fe8c`. Она не заменяет ASR, pyannote или LLM и не заявляет автоматического устранения ошибок распознавания.

## Возможности

- Словарь ФИО, регионов и терминов предлагает похожие слова: расстояние Левенштейна до двух, одинаковая первая буква, разница длины до одного символа. Поддерживаются буквы русского и казахского алфавитов. Несколько кандидатов сохраняются как варианты. «Атырауская → Павлодарская» автоматически не предлагается.
- Исправление имени, региона или даты связывается с существующей репликой и точным исходным фрагментом. Исходные `transcript`, `segments` и цитаты поручений не переписываются.
- Отсутствующая в ASR деталь добавляется вручную после прослушивания как «Дополнение по аудио», а не как цитата ASR. При неразборчивой записи используется «Нужно уточнить». Эталонный DOCX не является заменой аудиоисточника.
- Подтверждение говорящего действует только для выбранной реплики. Оно не распространяется автоматически на весь кластер pyannote и не назначает исполнителя.
- Исполнитель подтверждается отдельно со ссылкой на реплику и поручение. При добавлении через UI имя переносится в карточку, прежняя привязка к учётной записи очищается, остальная карточка остаётся на проверке. Сервер отклоняет подтверждение, если имя в карточке позднее изменили.
- Все положительные отметки требуют явного заявления пользователя о прослушивании. Это пользовательская аттестация, не автоматическое доказательство прослушивания или истинности.
- Отметки сохраняются вместе с обычным черновиком и попадают в JSON и отдельный раздел Markdown/DOCX/PDF. Правки утверждённого протокола блокируются. Старые клиенты, не передающие `source_review`, сохраняют существующие отметки.

## Проверка вручную

1. В готовом протоколе откройте «Сверка с аудио». Введите словарь по одному термину на строку.
2. Нажмите «Найти похожие слова». Выбор варианта только заполняет форму, ничего не исправляет автоматически.
3. Откройте выбранную реплику в аудиоплеере и прослушайте её. Введите результат, подтвердите прослушивание и добавьте отметку.
4. Для неразборчивого фрагмента выберите «Нужно уточнить» без подтверждения.
5. Нажмите общую кнопку «Сохранить». После перезагрузки проверьте отметки и отдельный раздел экспорта.

## API и хранение

`POST /api/meetings/{id}/source-suggestions`: `{terms: string[]}`, доступ только редакторам. Возвращает предложения без записи в базу.

`PUT /api/meetings/{id}/review`: необязательное поле `source_review` с `terms` и `notes`. Отметка содержит `kind`, `segment_id`, `original`, `text`, `action_id`, `audio_checked`. Типы: `correction`, `supplement`, `speaker`, `owner`, `uncertain`.

Данные находятся в существующем JSON тела совещания: отдельная миграция БД не требуется. Сохраняются стандартные контроль версии, аудит пользователя/версии и ограничения READ/EDIT. Администратору метаданных и аудитору содержимое не раскрывается.

## Проверки и ограничения

- Backend: 72 теста прошли, включая PostgreSQL/MinIO в отдельной тестовой базе, без удаления сохранённых протоколов.
- Frontend: 21 тест, TypeScript/Vite build и ESLint прошли.
- Проверены неизменность исходника, точные ссылки, запрет неподтверждённых утверждений, устаревшие версии, права доступа, сохранение отметок старым клиентом, дубли подтверждений, рассогласование исполнителя и включение отметок в Markdown/DOCX.
- В браузере локального Docker-стенда проверены отображение панели и предложение «Ботагус → Ботагоз». Полный сценарий сохранения через браузер не завершён: вкладка перестала быть доступна инструменту. Сохранение проверено API-тестами.
- Визуальная проверка страниц DOCX/PDF ещё не выполнена; LibreOffice/Poppler в доступных стандартных путях отсутствуют. Это не подтверждение полной готовности оформления.
- Словарь не является полноценной морфологией, не исправляет числа словами и не восстанавливает удалённую ASR речь. Дополнения не запускают повторный LLM-анализ и не изменяют автоматически саммари/сроки.
- Пользователь ещё должен прослушать спорные места реальных встреч. Автоматическое улучшение WER или точности голосовой идентификации не измерялось.
- Известное предупреждение старых тестов: `ResourceWarning` незакрытого SQLite-соединения; тесты проходят.

## Совместимость с работой команды
