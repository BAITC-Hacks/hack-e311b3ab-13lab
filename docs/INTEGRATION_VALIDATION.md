# Проверка объединённого проекта

Дата: 23 сентября 2026 года. Основа — GitHub main `ff7fe8c`. Повторный fetch в начале проверки не обнаружил новых коммитов команды. Коммит и push этой доработки не выполнялись.

## Что объединено

Сохранены backend/frontend, PostgreSQL, MinIO, авторизация и права доступа, утверждение протоколов, кеширование ASR и интеграция pyannote из GitHub. Перенесены доступные локальные изменения анализа: основания исполнителя, поручивший, ожидаемый результат, условия, альтернативные сроки, отдельное саммари, контроль числовых фрагментов. Добавлены отдельный endpoint Qwen3.6, ограниченные повторы HTTP/JSON и ручная сверка ASR/говорящих/исполнителей.

Это перенос доступного кода, а не подтверждение полного совпадения с ранее присланным текстовым описанием analysis v2. UI создания новой копии анализа не добавлен: повторная оценка выполняется CLI с отдельными выходными файлами. Старый проект `app/` и его незакоммиченные изменения сохранены в родительском каталоге.

## Реальные прогоны Qwen

Использован `qorytyn-qwen3.6-27b` через локальный SSH-туннель на H200. Входы — сохранённые ASR и результаты pyannote двух реальных совещаний; ASR и диаризация повторно не запускались. Эталонные DOCX не передавались модели. Исходные JSON не перезаписывались, их SHA-256 записаны в метаданные оценки. Дата 2026-09-23 — тестовая привязка сроков, не подтверждённая дата записей.

Последние результаты находятся в `backend/data/release-checked/` (игнорируются Git): 10 карточек в №1, 6 в №2. В №1 два исполнителя оставлены пустыми, в №2 — один. Это не установленная точность исполнителей: остальные машинные назначения также требуют проверки.

Первый интеграционный прогон обнаружил ошибочное массовое присвоение типа срока `event`. Исправлено: календарная фраза проверяется отдельно от метки модели. Выявлено и исправлено молчаливое предпочтение основного срока единственной альтернативе; «две недели» и «максимум десять дней» теперь сохраняются как конфликт с пустой датой. «По итогам этого совещания» восстанавливается из точной цитаты поручения как событие. «Больше недели» остаётся неопределённостью.

Проверка саммари выявила повторное назначение спорного исполнителя и превращение «больше недели» в «до недели». Саммари теперь получает проверенные ограничения карточек. В последнем просмотренном результате спорный срок обозначен как требующий уточнения. Отдельно обнаружена потеря отрицания внутри цитаты; неподтверждённые цитаты в кавычках «…» теперь заменяются видимой отметкой для проверки, а не публикуются как дословные.

## Почему это не 100% готовый автоматический протокол

Счётчик числовых фрагментов нестабилен между прогонами: промежуточно было 11/11 в обеих записях; после дополнительной сверки саммари — 10/11 и 0/11. Он сравнивает последовательности слов полного исходного фрагмента, игнорируя пунктуацию. 0/11 не означает отсутствие всех чисел: модель сохраняет показатели в более коротких цитатах и пересказе, но полные фрагменты не совпадают. Это не оценка истинности, не WER и не прежние восемь выбранных фактов. Нельзя показывать промежуточные 11/11 как стабильный итог последней версии.

Остаются ошибки распознавания имён/регионов/дат, неизвестные исполнители, пустые или неподтверждённые подробности, семантические ошибки вне прямых цитат и необходимость прослушивания. Контроль цитат не доказывает верность вывода модели. Pyannote не устанавливает ФИО автоматически. Заявления о 100% покрытии или правильности всех полей не делаются.

## Воспроизведение

```sh
cd backend
../.venv/bin/python -m unittest discover -s tests
TEXT_BASE_URL=http://127.0.0.1:8769/v1 TEXT_MODEL=qorytyn-qwen3.6-27b TEXT_ENABLE_THINKING=false \
  ../.venv/bin/python -m scripts.evaluate_saved input1.json input2.json --output data/new-evaluation
cd ../frontend
npm test
npm run build
npm run lint
```

Без HATTAMA_TEST_DATABASE_URL/HATTAMA_TEST_MINIO_ENDPOINT интеграционный тест пропускается. Он очищает указанную тестовую базу: не задавайте адрес базы с нужными данными. Секреты задаются только через окружение, не коммитятся.

`evaluate_saved --postprocess-only` предназначен только для машинных результатов оценки; не использовать на ручных протоколах. `--refresh-summary` добавляет новый запрос саммари. Эти режимы сохраняют результаты в другой каталог, не изменяя исходник.

Итог: объединённый кандидат для ручной приёмки. Перед публичной демонстрацией проверить спорные фрагменты и последние экспорты. Не объявлять модель полностью автономной и безошибочной.
