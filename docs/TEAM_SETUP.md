# Запуск HATTAMA.AI для команды

Инструкция для участников команды 13Lab: как поднять весь проект у себя через Docker и войти.

## Что нужно

- Docker Desktop (или Docker Engine с Compose v2). Проверка: `docker compose version`.
- Git.
- Свободные порты `8080` (интерфейс) и `9001` (консоль MinIO).
- Ключ `TILQAZYNA_API_KEY`. Попросите его у Даркхана в личном сообщении, не в общем чате.

Python и Node.js ставить не нужно: всё собирается внутри контейнеров.

## Первый запуск

```bash
git clone https://github.com/BAITC-Hacks/hack-e311b3ab-13lab.git
cd hack-e311b3ab-13lab
cp .env.example .env
```

Откройте `.env` и впишите ключ в строку `TILQAZYNA_API_KEY=`. Остальное можно не трогать. Файл `.env` не коммитится: он в `.gitignore`.

```bash
docker compose up --build
```

Первая сборка занимает несколько минут. Когда сборка закончится, откройте <http://127.0.0.1:8080>. Если страница не открывается, проверьте в другом терминале `docker compose ps -a`: `migrate` должен завершиться с `Exited (0)`, `backend` быть `healthy`.

Чтобы терминал оставался свободным, запускайте в фоне: `docker compose up -d --build`.

## Логины и пароли

| Email | Пароль | Роль | Для чего |
| --- | --- | --- | --- |
| `admin@hattama.local` | `change-me-admin-password` | Администратор | Полный доступ: все совещания и протоколы, пользователи, заявки, журнал, админ-панель |
| `team@hattama.local` | `hattama-team-2026` | Секретарь | Загрузка записей, проверка, утверждение и выгрузка протоколов |

Эти значения берутся из вашего `.env` (`ADMIN_EMAIL`, `ADMIN_PASSWORD`, `SEED_PASSWORD`). Если вы их поменяли до первого запуска, входите со своими.

Учётные записи создаются один раз, при первом запуске. Если потом поменять пароль в `.env`, существующая запись не изменится: смените пароль в интерфейсе (кнопка «Пароль» внизу меню) или сбросьте данные командой из раздела «Полный сброс».

Пароли из примера годятся только для локального запуска. Если стек доступен по сети, замените их в `.env` до первого запуска.

## Что проверить после входа

1. Войдите как `team@hattama.local`, нажмите «Новое совещание» и загрузите короткую запись. Статус обновляется сам.
2. Когда появится черновик, проверьте поручения и нажмите «Утвердить».
3. Выйдите и войдите как `admin@hattama.local`: откроется админ-панель.
4. На странице входа есть ссылка «Зарегистрироваться». Новая заявка появится в админ-панели; одобрите её и выберите роль.

## Адреса

| Что | Адрес | Вход |
| --- | --- | --- |
| Интерфейс | <http://127.0.0.1:8080> | Учётные записи выше |
| Документация API | <http://127.0.0.1:8080/docs> | Токен из `POST /api/auth/login` |
| Консоль MinIO | <http://127.0.0.1:9001> | `MINIO_ROOT_USER` / `MINIO_ROOT_PASSWORD` из `.env`, в примере `hattama` / `change-me-minio-password` |

PostgreSQL и backend наружу не публикуются. Подключиться к базе:

```bash
docker compose exec postgres psql -U hattama -d hattama
```

## После git pull

```bash
git pull
docker compose up -d --build
```

Сервис `migrate` сам применит новые миграции базы и создаст новые командные учётные записи, затем стартует backend. Данные сохраняются.

Если в `.env.example` появились новые переменные, перенесите их в свой `.env`. Строки со знаком `<` в выводе этой команды есть в примере, но отсутствуют у вас:

```bash
diff <(grep -o '^[A-Z_]*=' .env.example | sort) <(grep -o '^[A-Z_]*=' .env | sort)
```

## Полезные команды

| Задача | Команда |
| --- | --- |
| Статус сервисов | `docker compose ps -a` |
| Логи backend | `docker compose logs -f backend` |
| Что сделали миграции | `docker compose logs migrate` |
| Остановить, данные сохранятся | `docker compose down` |
| Пересобрать только интерфейс | `docker compose up -d --build frontend` |
| Применить миграции вручную | `docker compose run --rm migrate` |
| Применить изменения в `.env` | `docker compose up -d --force-recreate backend` |

Новая общая учётная запись: добавьте строку в `backend/seed/users.json`, закоммитьте, и после `git pull` и `docker compose up -d --build` она появится у всех с паролем `SEED_PASSWORD`.

## Полный сброс

Удаляет базу, записи и протоколы, затем создаёт учётные записи заново из `.env`:

```bash
docker compose down -v
docker compose up --build
```

## Если что-то не работает

| Симптом | Что сделать |
| --- | --- |
| `set POSTGRES_PASSWORD in .env` или похожая ошибка при запуске | В `.env` не хватает переменных. Скопируйте недостающие строки из `.env.example` |
| `port is already allocated` | Порт занят. Добавьте в `.env` строку `APP_PORT=8081` и откройте <http://127.0.0.1:8081> |
| Пароль из таблицы не подходит | Запись создана раньше с другим паролем. Войдите старым паролем или выполните полный сброс |
| «Ключ сервиса моделей не задан» в правом верхнем углу | Впишите `TILQAZYNA_API_KEY` в `.env` и выполните `docker compose up -d --force-recreate backend` |
| Обработка записи завершилась ошибкой | Проверьте ключ и доступ к `router.tilqazyna.kz`, затем нажмите «Повторить обработку» |
| «Учётная запись ожидает подтверждения администратора» | Войдите как администратор и одобрите заявку в админ-панели |
| Остались контейнеры старой версии (`qorytyn` или `hack-e311b3ab-13lab-*`) | `docker compose -p hack-e311b3ab-13lab down -v`, затем обычный запуск |

Разработка без Docker, тесты и все переменные описаны в [README](../README.md).
