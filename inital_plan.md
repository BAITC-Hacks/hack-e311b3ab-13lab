1. Фиксируем объём первой версии
Делаем один веб-интерфейс с четырьмя последовательными шагами:
1. Загрузка: аудиофайл, название и дата совещания, необязательный список участников.
2. Расшифровка: реплики, время, говорящие; возможность исправить текст и сопоставить «Говорящий 1» с именем.
3. Поручения: редактируемая таблица «задача / ответственный / срок / источник».
4. Результат: краткое содержание и скачивание протокола в DOCX.
Главная полезная функция: нажатие на источник поручения открывает соответствующий фрагмент аудио. Пользователь может проверить, откуда взялись исполнитель и срок.
Zoom/Teams, прямой эфир, рассылки, СЭД и напоминания откладываем. Для этого плана предполагаем, что загрузка записи подходит для сдачи; формулировку про подключение к конференциям стоит уточнить у организаторов.
2. Выбираем простой стек
Компонент	Решение
Интерфейс и управление обработкой	Python + Streamlit
Подготовка аудио	FFmpeg → WAV, mono, 16 kHz
Распознавание речи	faster-whisper, стартовый кандидат — Whisper large-v3
Разделение по говорящим	pyannote Community-1
Поручения и саммари	Локальная Qwen3 8B через Ollama как стартовый кандидат
Проверка структуры результата	Pydantic
Экспорт	python-docx
Хранение	Локальные файлы: аудио, транскрипт, результат JSON


faster-whisper поддерживает GPU, а Community-1 допускает офлайн-работу после скачивания моделей. Для pyannote необходимо заранее принять условия доступа и скачать веса. faster-whisper, Community-1, Qwen3 8B
Выбор размеров моделей предварительный: характеристики выданного GPU неизвестны. Если памяти мало, этапы запускаем последовательно с освобождением памяти; пригодность моделей проверяем на коротком фрагменте до разработки интерфейса.
Весь путь обработки аудио и текста работает локально либо в разрешённом закрытом контуре. Код приложения не должен отправлять содержание совещаний во внешние API.
3. Реализуем обработку в таком порядке
А. Аудио → текст и говорящие
Распознавание возвращает слова или сегменты с временными отметками. Диаризация возвращает интервалы говорящих. Объединяем их по пересечению времени.
Для неоднозначных участков показываем «Говорящий не определён». Имена предлагаем по контексту и списку участников, но позволяем подтвердить или исправить сопоставление.
Важно: говорящий и исполнитель поручения — разные поля. Руководитель может поручить работу человеку, который вообще не выступал.
Б. Транскрипт → поручения
Передаём локальной модели транскрипт с идентификаторами реплик, дату совещания и список участников. Для каждого поручения сохраняем:
Поле	Для чего
Формулировка задачи	Что именно нужно сделать
Ответственный	Человек или подразделение; может быть не указан
Срок исходной фразой	Например, «до пятницы»
Дата или период	Только когда можно однозначно определить
Источники	Идентификаторы реплик и проверяемые цитаты
Требуется уточнение	Причина: неизвестный исполнитель, конфликт сроков и т. п.


Правила извлечения:
- объединять повторное упоминание одной задачи;
- учитывать явно согласованные изменения;
- отличать предложение от принятого поручения;
- сохранять условия: «если нарушают — расторгнуть» не превращать в безусловное расторжение;
- не придумывать отсутствующих исполнителей и сроков;
- при противоречии сохранять обе формулировки и отмечать необходимость проверки.
После ответа модели проверяем структуру, существование указанных реплик и соответствие цитат исходному тексту. Некорректный ответ не показываем как готовый протокол.
В. Проверка человеком → экспорт
Секретарь исправляет поручения и нажимает «Сформировать протокол». DOCX содержит название, дату, участников, краткое содержание и таблицу поручений. Неуточнённые поля остаются явно обозначенными.
4. Расписание на пять часов
План рассчитан на доступный GPU и возможность скачать модели. Если окружение ещё не подготовлено, это главный риск срока.
Время	Работа	Проверяемый результат
0:00–0:40	Окружение, модели, короткий фрагмент аудио	Все три модели запускаются; получены текст, говорящие и хотя бы одно поручение
0:40–1:30	Полный аудиопроцесс и сохранение промежуточных результатов	Первая запись обрабатывается целиком, реплики связаны с временными отметками
1:30–2:25	Извлечение поручений, сроки, объединение повторов, проверка JSON	Получена таблица с источниками, ошибки видны
2:25–3:15	Интерфейс: загрузка, прогресс, аудио, правки	Можно пройти весь сценарий без изменения кода
3:15–3:45	Саммари и DOCX	Скачанный документ открывается и содержит подтверждённые данные
3:45–4:30	Проверки на двух записях и RU/KZ/смешанной речи	Зафиксированы результаты и исправлены критические ошибки
4:30–5:00	README, повторный запуск, подготовка демо	Решение запускается по инструкции и проходит демонстрационный сценарий


Контрольная точка на 40-й минуте: если модели не запускаются, сокращаем время на оформление и дополнительные функции. Замена аудио готовым текстом допустима для отладки, но не закрывает обязательное распознавание речи.
5. Как проверяем на твоих файлах
Протокол №1 используем для настройки. Протокол №2 — для отдельной проверки после первой рабочей версии. Готовые саммари и таблицы из DOCX не подаём модели вместе с входным диалогом: иначе проверка будет фактически копированием ответа.
Обязательные проверки по содержанию:
Ситуация	Ожидаемое поведение
Аудит сначала обсуждают на две недели, затем называют 15 октября	Сохранён итоговый срок; задача не продублирована
Поручение повторяют в конце встречи	Одна задача с несколькими источниками
Претензию должен подготовить Ерлан	Исполнитель — Ерлан, хотя он не выступает
Для задачи Салтанат срок не назван	«Не указан»
«Пять рабочих дней» — условие будущего договора	Не назначено сроком подготовки самого договора
«После совещания с подрядчиками»	Сохранена зависимость от события, не придумана дата


Таблицы в образцах — ориентир, а не безошибочный эталон: при расхождении проверяем сам диалог и аудио.
Дополнительно нужны короткие записи на казахском и со смешанной речью, если имеющиеся их не содержат. Проверяем не только текст, но и сохранность имён, действий и сроков.
